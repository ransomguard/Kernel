# RansomGuard v0.4.0 — Unload Protection (미니필터 자기보호)

미니필터가 관리자 권한의 `fltmc unload`로 손쉽게 해제되던 구멍을 메워,
탐지 계층이 스스로를 보호하도록 한 버전입니다.

**변경일:** 2026-09-23
**이전 버전:** `v0.3.2_selfprotect-logfix`

---

## 이번 버전의 핵심 — 보안 컴포넌트 자기보호

이 프로젝트의 주제는 "보안 컴포넌트의 자기보호(무력화 시도 대응)"입니다.
기존 커널 드라이버는 등록된 엔진 프로세스를 보호(`ObRegisterCallbacks`)했지만,
파일 암호화를 탐지하는 미니필터(`Anti_Ransom_FsFilter`)는 자기보호가 없어,
관리자 권한의 `fltmc unload` 한 번으로 탐지 계층이 통째로 해제되는 구멍이
있었습니다. 이번 버전이 이 구멍을 메웁니다.

| 컴포넌트 | 보호 대상 | 수단 |
|---|---|---|
| 기존 드라이버 (ARWDrv) | 등록된 엔진 프로세스 | ObRegisterCallbacks (권한 박탈) |
| **미니필터 (FsFilter)** | **미니필터 자신의 해제** | **언로드 콜백 거부 (이번)** |

---

## 동작 방식

미니필터의 언로드 콜백에서, 자발적 해제(`fltmc unload`) 요청을 조건부로
거부합니다.

- **자발적 해제 거부:** 보호가 켜져 있으면 언로드 콜백이 `STATUS_FLT_DO_NOT_DETACH`를
  반환해 `fltmc unload`를 실패시킵니다.
- **강제 해제 보존:** 시스템 종료 등 강제 언로드(`FLTFL_FILTER_UNLOAD_MANDATORY`)는
  절대 거부하지 않습니다. 종료를 막으면 안 되기 때문입니다.
- **핫패스 무영향:** 보호 로직은 로드 시 1회, 언로드 시 1회만 동작합니다.
  파일 쓰기(pre-write) 경로 코드는 바뀌지 않아 성능에 영향이 없습니다.

---

## 킬 스위치 (개발자 탈출 경로)

자기보호가 개발자 자신을 잠그지 않도록, 레지스트리 킬 스위치로 켜고 끕니다.
기존 드라이버 SelfProtect와 동일한 규율입니다.

| 항목 | 값 |
|---|---|
| 키 | HKLM\SYSTEM\CurrentControlSet\Services\Anti_Ransom_FsFilter\Parameters |
| 값 이름 | EnableUnloadProtection (REG_DWORD) |
| 기본값 | 0 (꺼짐). 값이 없거나 0이면 정상 해제 |

값 이름을 기존 드라이버의 `EnableSelfProtect`와 다르게 둔 이유는, 동작이
서로 다르고(프로세스 보호 vs 언로드 방어) 서로 다른 서비스 키에 있어
이름을 통일할 실익이 없기 때문입니다.

---

## 아키텍처 — 분리 유지

미니필터는 기존 드라이버와 분리된 별개 .sys 상태를 유지합니다.
언로드 방어 로직은 미니필터 자신의 서비스 키만 읽으며, 두 드라이버 간
커널 통신이나 공유 코드를 추가하지 않았습니다. 각 컴포넌트가 독립적으로
자기보호를 수행하므로, 한쪽이 무력화되어도 다른 쪽은 영향을 받지 않습니다.

## 검증 결과 (VM)

VMware Win11 (26100), testsigning on.

| 상태 | fltmc unload | 결과 |
|---|---|---|
| 보호 꺼짐 (기본, EnableUnloadProtection=0) | 정상 해제 | 통과 |
| 보호 켜짐 (EnableUnloadProtection=1) | 거부 (REFUSED) | **자기보호** |
| 킬 스위치로 해제 후 | 다시 정상 해제 | **탈출구** |

DebugView 로그로 각 상태의 전환을 확인했습니다:
`Unload self-protect: ON` / `Unload REFUSED by self-protect` / `Unload self-protect: OFF`.

> "켜면 해제 거부, 킬 스위치로 끄면 다시 해제"의 세 상태가 모두 확인되어,
> 미니필터 자기보호와 개발자 탈출 경로가 함께 동작함을 실증했습니다.

## 변경 범위

- `FsFilter.c` 한 파일: 전역 플래그, 자기완결 레지스트리 리더, DriverEntry의
  레지스트리 1회 읽기, 언로드 콜백 본문 수정.
- `SETUP_MINIFILTER.md`: 자기보호 검증 절차(값 변경 → 재로드 → 해제 거부 확인
  → 킬 스위치 해제) 추가.
- 다른 파일과 기존 드라이버는 건드리지 않았습니다.

---

## 알려진 한계

1. **관리자 권한 환경의 한계** — 킬 스위치가 레지스트리 기반이므로, 관리자
   권한을 가진 공격자가 값을 0으로 바꾸고 재부팅하면 해제할 수 있습니다.
   상용 제품 수준의 방어(ELAM, PPL 등)는 이 범위를 벗어납니다.
2. **엔트로피 탐지 회피** — 느린 속도 암호화나 부분 암호화로 엔트로피를 낮추면
   미니필터 탐지를 회피할 수 있습니다. 기존 드라이버의 VSS 선행 행위 차단이
   이를 부분적으로 보완합니다.
